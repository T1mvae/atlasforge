# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

AtlasForge is a browser-based editor for political / historical / alternate-history world maps. **Live:** https://t1mvae.github.io/atlasforge/

## Commands

- **Build** (required after editing anything under `js/`, `css/`, `icons/` or `tools/sw.template.js`): `npm install` once, then `npm run build` (`tools/build.mjs`). It:
  - copies the UMD libraries into `vendor/` (the app has **no CDN dependencies** — it must work offline as an installed PWA);
  - precompiles `js/*.jsx` → `build/*.js` with the **same Babel 7.29.0 presets (`react` + `env`) the in-browser transformer used**, so the output stays classic scripts whose top-level declarations are shared globals, exactly like before;
  - stamps every local asset URL in `index.html` / `Map Editor.html` with a content hash `?v=` (GitHub Pages sends `max-age=600`; without the stamp a returning visitor keeps old files);
  - writes `sw.js` from `tools/sw.template.js` (precache list + version);
  - writes `dev.html` — the same page loading `js/*.jsx` through in-browser Babel, for iterating without rebuilding (no service worker there).
  `build/`, `vendor/`, `sw.js`, `dev.html` and the stamped HTML are **committed**: Pages serves the repo root of `main`, there is no CI build.
- **Run locally** (required — the app `fetch`es `data/*.geojson`, so `file://` fails): serve over HTTP, then open `index.html` (built) or `dev.html` (live JSX).
  ```bash
  python3 -m http.server 8123    # .claude/launch.json defines this as the "map-editor" config
  ```
- **No test suite, no linter.**
- **Deploy:** `npm run build`, commit, push to `main` → GitHub Pages serves the repo root. The sandboxed preview browser cannot load the github.io URL — verify deploys with `curl`/`gh` (HTTP 200 + grep the deployed `js/`).
- **PWA / service worker** (`js/pwa.js`, `sw.js`): shell assets are precached and served cache-first (hashed URLs); `data/*.geojson` is cached on first use (cache `af-data-v1`); navigations are network-first with an offline fallback. A new version waits until the user taps "Reload" in the banner. The in-app preview browser cannot register service workers — test offline behaviour with headless Chrome (e.g. puppeteer-core against a local server, `page.setOfflineMode(true)`).
- **Regenerate map data** (rarely): `python3 tools/build_*.py` then `npx mapshaper` to simplify. Source mods live in git-ignored folders (`OWB_helping_files/`, `World_helping_files/`); the app only ever loads from `data/`. Base datasets are never modified by the editor.
  - AGOT (CK3): `python3 tools/build_agot_from_mod.py` + `tools/build_agot_terrain.py`, both reading `map_data_agot/` through **`tools/agot_source.py`, which composites the official base mod with the submod folders nested inside it** (`LAYERS`, in priority order). The official map is always authoritative; every submod may only fill what the official map leaves blank (a huge impassable block = world the mod has not made yet). An earlier submod keeps its additions over a later one. Every layer's ids carry its own offset because the submods re-use the raw numbers for different places.
    - Title hierarchy: base + LoV carry it in the banner comments of `provinces/*.txt` (two different formats — `parse_base` / `parse_overlay`). The Summer Isles and Essos Expanded ship **no titles at all**, so the builder derives them: Summer Isles = one county per named barony, duchies = the landmasses; Essos Expanded = kingdom per culture (its only real per-province data), duchy per contiguous stretch of that culture, counties k-means-clustered to `FAR_EAST_COUNTY` baronies so the far east stays as paintable as the rest. Derived titles carry `generated: true`.
  - `map_data_essos_expanded` and `map_data_further_east` are the same mod one revision apart (identical rasters, one province differs); `further_east` supplies the geometry and `essos_expanded` the `k_generated.txt` cultures.
    - After rebuilding the four political GeoJSON files, run Mapshaper with `-simplify dp 25% keep-shapes -o format=geojson precision=0.01`. This preserves shared topology and IDs while keeping the web payload manageable; committing the unsimplified builder output makes AGOT several times slower to load.

## Architecture

Static site, classic scripts (JSX precompiled by `npm run build`). Everything hangs off `window` globals; there are no modules/imports.

**Load order** (from `index.html` / `Map Editor.html`): `vendor/` libs → `js/i18n.js` → `core.js` → `storage.js` → `pwa.js` → `geo.js` → `regions.js` → `export.js` → `edit.js` → `terrain-algos.js` → `world.js` → `atlas.js` → `names.js` → `objects.js` → `build/map.js` → `build/world.js` → `build/objects.js` → `build/panels.js` → `build/chrome.js` → `build/app.js` (the `build/` files are `js/*.jsx` precompiled). Edit the sources in `js/`, never `build/`.

**Global singletons:** `App` (state, `App.version`, `emit`/`subscribe`), `Actions` (every mutation + undo/redo), `Geo`, `RegionModel`, `GeomEdit`, `Exports`, `ColorUtil`, `BASEMAPS`, `MAP_STYLES`, `t()`. React components read `App.version` via `useSyncExternalStore`; **all state changes go through `Actions.mut(fn, opts)`** (the single write + undo entry point) — never mutate `App.project` directly.

**Module responsibilities:**
- `core.js` — the heart: `App`, project schema (`newProjectData`), all `Actions.*`, undo/redo, `MAP_STYLES`, `ColorUtil`, localStorage autosave.
- `geo.js` — basemap loading/processing: the `BASEMAPS` registry, `Geo.load`, projection auto-pick, client-side topology build, `buildEditableResult`, `processGeo`/`processPixelGeo`/`processRegions`.
- `regions.js` — `RegionModel`, the **mid-level region-layer** system (custom regions with real geometry, layers, per-region edit diffs).
- `edit.js` — `GeomEdit`: geometry editing (merge/split/draw/vertex-edit) + `politicalClone` (carries owner/status/etc. across geometry edits).
- `export.js` — `Exports`: SVG/PNG/JSON export and import. **Pictures** (`ExportModal` in chrome.jsx → `Exports.startPng(size)`) show the map on a *virtual screen*: `SIZES` normal (2 px/unit, the whole map as fitted to a screen, 4× sharp), large (4 px/unit) and huge (8 px/unit, as if zoomed in). `prepareClone` copies the live `#map-svg` without `data-export-skip` nodes or selection, embeds the CSS the map needs (`embeddedStyle`: country labels, place icons and names, `vector-effect`), sizes places for the virtual zoom (`objectTransform(o, kv, FIT_PPU)`) and scales screen-pixel strokes by the density. `renderPng` draws horizontal bands of ≤ 8 Mpx (iOS canvas limit ~16.7 Mpx): terrain straight onto the canvas at full resolution (`World.renderTerrain` — per-cell colours blended bilinearly, the coast a sharp antialiased line), then the SVG with that band's `viewBox`; bands go through a streaming PNG writer (`CompressionStream("deflate")` + CRC32 chunks), so 16000×8160 never needs one canvas. On the iPad the finished file is saved by a tap on "Сохранить / Поделиться" (`Exports.saveResult`) — the share sheet needs a fresh gesture; desktop downloads at once. Anything that must not appear in pictures gets `data-export-skip`.
- `map.jsx` — the SVG map canvas: rendering, zoom/pan, tools, fill resolution (`regionFill`), status stripe `<pattern>`s, `ownerUnionPath` borders, labels/markers. **Map text** (free labels `project.labels` and country names) goes through one renderer, `MapText` (`freeLabelText` / `stateLabelText` build its input): `angle`, `curve` (−1…1, an arc via `<textPath>` on `mapTextArc`, longer than the text so no letter drops), `spacing`, `italic`, `upper` (done in JS, not CSS), `halo`/`haloColor`, `shadow` (`#lblShadow`). Free labels keep these keys on the record (null removes one, `Actions.setLabel`); country names in `state.labelStyle`. A tap selects (`selectText` → `App.ui.card` kind `label` / `stateLabel`, rendered by `LabelCard` in panels.jsx with `TextStyleFields`; fingers select too); the selected text shows a frame and two handles (`#label-handles`, `data-lhandle` turn / bend, hit-tested before places and finger navigation, one undo step per drag). Hit-test text with `closest("[data-label]")` — `<textPath>` children are the event targets.
- `panels.jsx` — the left toolbar (`Icons`, `TOOLS`, `GEOM_TOOLS`), right-side property panels (Map / State / Region tabs) + reusable form primitives (`Field`, `TextField`, `SelectField`, `ComboField`, `Check`).
- `world.js` — `World`: the **custom world** basemap (`kind: "world"`). **What is painted is what the map shows — nothing is simulated while painting** (no automatic rivers, lakes or biomes; the user asked for that). Painted rasters in memory: `World.height` (Int16 metres, `RW×RH` = 2000×1020, `RES` = 2 cells per data unit) and `World.cover` (Uint8 `COVER` index, 0 = nothing painted). Brushes (relief, cover, line tools ridge/valley/river) work on per-stroke base copies and push **raster diff undo entries** (`Actions.pushUndoEntry`). Rivers are plain polylines (`project.world.rivers`, source → mouth; `finishRiver` only turns a stroke drawn from the mouth round and snaps a mouth onto the river it joins); their network (into / Strahler order / upstream length) comes from `TA.riverNetwork` in `World.displayRivers`, which also resolves the parameters — `order`, `size` (0 stream … 3 great river, by length with tributaries, sets the drawn width), `navigable`, `major` — each automatic unless set by hand in the river card (`rv.manual`, `World.setRiverManual`). All river-list edits go through `commitRivers` (a **new array** every time — caches are keyed by array identity — plus a "rivers" undo entry). The card's source/mouth handles (`#river-ends` in map.jsx) drive `World.endEditStart/Move/End`: sliding along the river cuts it (`TA.cutPolyline`), pulling off it draws a new course, a mouth released on another river joins it; `World.reverseRiver` swaps source and mouth. Rendering: an HTML `<canvas>` (Horn hillshade, cover colours, snow above `world.snowline`) placed *under* the SVG by `World.place`. **"Поправить географию"**: `World.runGeography(opts)` runs `TA.geography` in `js/terrain.worker.js`, the result is shown on a second canvas (`World.preview`, hold-to-compare via `World.setCompare`) and committed by `World.applyGeography` as one raster undo entry (or dropped by `World.cancelGeography`; undo/Escape also drop it). Painting is blocked while a preview is open. `World.ensureAnalysis` runs climate + basins on demand (smart provinces, atlas climate) — never drawn. **Landmasses come from the raster** (`World.landTopology` → `TA.landTopology`, cached per `rasterRev`; `World.dataGrid().landId`): a data cell is land when any sub-cell is, so a strait one raster cell wide vanishes on the data grid — everything that asks "same land?" (the cut, the atlas) must use `landId`, never `h > 0` connectivity. **Province cut:** `World.generate` runs smart provinces in the worker and shows the result first (`World.cutPreview`: red borders in map.jsx, `CutBar` report, "what the borders follow" canvas `World.whyCanvas` from `why`); `World.applyCut` writes `project.customGeo` (properties `terrain`, `coastal`, `basin`, `isthmus`, `islets`) and resets undo, `World.cancelCut` (or undo) drops it; painting is blocked meanwhile.
- `terrain-algos.js` — `TerrainAlgos`: pure typed-array algorithms shared by page and worker on the **data grid** (1000×510): climate, Priority-Flood, flow/accumulation, evaporation-balanced lakes, rivers + Strahler order, basin merging, **smart provinces** (blocks by landform × basin → geodesic Voronoi atoms → crest-aware merging: a province never contains mountain pieces separated by a crest), exact label polygons and per-arc topology smoothing, the drawn-river network, and **`TA.geography`** — the on-request pass over the painted rasters (foothills, erosion, drawn rivers oriented / led on to water along a least-cost path / carved so the bed never rises, lakes, rivers + tributaries from runoff, biomes painted as cover on unpainted land). Smart provinces also guarantee: never two landmasses in one province (except islets joined to the nearest coast — specks always, islets with `provinceOpts.joinIslets`), never across an **isthmus** (thin land by exact morphological opening, `TA.landLevels` over `TA.edt2`, whose removal leaves two pieces ≥ `minSide`), every province one piece; growing over narrow land costs more so borders settle on necks. It returns `meta` per province and `why` per cell (1 strait, 2 isthmus, 3 river, 4 crest) plus a `report`; test it with a synthetic raster in Node (straits at odd/even raster columns, a diagonal one, a short neck to a peninsula). `TA.geography` is written to be **idempotent** (running it twice changes almost nothing: foothills are a level not an increment, beds are carved below their banks, unnamed `auto` rivers are replaced) — keep it that way. Test it in Node (`globalThis.self = globalThis; require(...)`).
- `atlas.js` — `Atlas`: `analyze` (province/landmass/water/range statistics on the data grid; landmasses from `dg.landId`), `provinceLine` (where a province lies — land, slope of a range, river, coast — shown in the region panel via `ProvinceGeo`), `areas` (neighbouring provinces of one owner grouped by shared geography — same landmass, landform, basin, coast, river — about eight to an area, named descriptively by direction + kind with the sea / range / river in brackets, or by a map label inside; `isDefaultName` tells "Провинция 12" from a real name), `remapPolitics` (owners carried across re-cuts by pixel-overlap vote), `names`, `build` (the Markdown atlas for AI; `detail`: "overview", "areas" — the default, states described by their areas — or "provinces", every province under its area). `world.jsx` holds the palette, the geography options sheet (`GeoSheet`) and preview bar (`GeoBar`), size rail, river card and atlas modal.
- `names.js` — `NameGen`: invented names by a user rule (start letters, example names → letter chain + recombined syllables, endings, length; with geography a shared root per area — landmass + basin — and a fitting element for mountain / coastal / forest / river provinces). Pure, testable in Node. The region panel's "Назвать по правилу…" opens `NameRuleModal` (world.jsx); names go through `Actions.setRegionNames(names, { auto, rule })` in one undo step: rule-made names carry `nameAuto: 1` (a later rule may replace them), typing a name clears it, hand-typed names are never replaced unless asked; the last rule is kept in `project.world.nameRule`.
- `objects.js` / `objects.jsx` — `Objects`: places (`project.objects`: cities, fortresses, ports, and fantasy ones — dragon's lair, portal, wizard's tower… — with founded/destroyed years for the timeline) and routes (`project.roads`, A* over the data grid on custom worlds, straight lines elsewhere). A place type is `{ id, size, city?, group }` in `TYPES` (groups `GROUPS` order the palette and card) plus an `OBJ_ICON` entry (16×16, stroke-only, anchored bottom-centre; colour only via CSS classes `obj-accent` gold, `obj-magic` violet, `obj-danger` red, `obj-hole` dark opening, `obj-line` unfilled) and `obj.type.<id>` in both i18n blocks. **Land roads follow the roads already built**: `routeOnWorld` rasterises the other road/trail lines, a step along them costs `FOLLOW` (0.75, heuristic scaled to stay admissible, no ford where a road already crosses), and runs along an existing road take that road's exact line (`TA.nearestOnPolyline` + `TA.cutPolyline`) so shared stretches coincide and forks lie on the old road; the road bar's "По существующим дорогам" chip (`App.ui.roadFollow`) turns it off; sea routes ignore roads. Roads draw sea → trail → road so a shared stretch shows the road. Positions are **map coordinates** (like labels), so places work on every basemap. Icons are SVG `<symbol>`s; `applyView` rescales them imperatively so they keep a screen size without a React render per zoom step. Tapping a place or a river opens a card (`App.ui.card`, rendered by `WorldCard`).
- `chrome.jsx` — top bar, menus, legend, timeline, template/new-project modal, project library, quick menu. `i18n.js` — EN + RU dictionaries (UI defaults to RU). `css/editor.css` — the only stylesheet.

## Data model — "region" is overloaded (read carefully)

- `project.states` = **countries**.
- `project.regions[featureId]` = per-base-feature **political/ownership records** (`{owner, status, color, name, group, autonomyId, ...}`). Despite the name these ARE the base-map cells (provinces / state-cells). **Always resolve through `window.effRegion(p, id)`**, which substitutes the merge-group's record when a cell belongs to a group.
- `project.groups` = legacy merged-cell groups (one shared political record for many cells).
- `project.catalogs` = reusable dictionaries for cultures, religions, languages and forms of government. Records keep `{name, color, parent, description}`; actual state/region fields deliberately store the display name, so `Actions.saveCatalogEntry` can rename every current and timeline use safely.
- `window.RegionModel` (`regions.js`) = a **separate** mid-level region layer — do not confuse it with `project.regions`.
- Imported geometry is re-derived from `data/*.geojson` on every load and is never stored in the project JSON; only diffs/edits/political data persist. Exceptions: `customGeo` (GeoJSON import / generated world provinces) and `project.world` (version 2: settings incl. `snowline`, `geoOpts` (last geography options), `rivers` polylines (`auto: true` = added by the geography pass), `riverNames` — only in worlds from the simulated-river version, applied to the rivers the pass adds; such worlds also get `legacyAuto` (a one-time palette note), `rasters` — `{w, h, height: ArrayBuffer, cover: ArrayBuffer}` written by `World.pack` right before a save; files/localStorage get base64 via `World.exportable`). Version-1 worlds (`elev`/`cover` RLE strings) are migrated on open. The undo slice carries `World.sliceWorld(p.world)` (no rasters). Regenerating provinces resets `regionGeomEdits`, groups and the undo stacks because every province id changes.

## Invariants & gotchas (each spans multiple files)

- **Undo allow-list:** `politicalSlice(p)` in `core.js` is an explicit list of project fields captured for undo/redo. Any **new top-level project field must be added there** or it is silently lost on undo (whole-project autosave/export already cover new fields).
- **Undo stack holds two kinds of entries:** JSON slice strings (`pushUndo` / `beginStroke`) and objects `{ undo(), redo(), bytes }` (`Actions.pushUndoEntry`, used for terrain rasters). `Actions.undo/redo` dispatch on `typeof`; the stack is capped by count and bytes.
- **Map colors are inline SVG attributes**, not CSS — driven by `project.settings` (`sea`/`land`/`borders`/`labelColor`/`labelFont`, spread from `MAP_STYLES`). `Actions.applyStyle(name)` overwrites those keys. Themed text uses an inline `style` to beat the `.country-label` CSS rule. `css/editor.css` only themes the app shell (via `data-theme` light/dark CSS vars).
- **Ring winding:** `d3.geoPath` needs exterior rings **clockwise** in planar lon/lat (reverse of RFC 7946); wrong winding renders a polygon as the entire sphere. Load-time `rewindForD3`/`orient` fix this — preserve it when touching geometry.
- **`bm.raw`:** region-grid / localgeo / pixelgeo basemaps ship raw GeoJSON, enabling topology-independent country borders (`ownerUnionPath`, polygon-union per owner) and autonomy overlays. TopoJSON basemaps fall back to arc meshes (`Geo.stateMesh`); union-based features are skipped there.

## Verifying changes in the browser

- **Rebuild first:** `index.html` runs `build/*.js`; after editing a `.jsx` run `npm run build` (or test on `dev.html`).
- **Stale-JS cache:** a same-port reload serves cached `js/*` (both plain scripts *and* the Babel `.jsx`). To pick up edits reliably, load on a **fresh port** (new origin = fresh cache) — start another `python3 -m http.server <newport>` and navigate there.
- **Screenshots lag React:** confirm state by reading `App.*` / the DOM via `javascript_tool` / `read_page`, not from a screenshot taken right after an action.
